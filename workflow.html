Pipeline map: assignment, and the family/subfamily fork

What each step of the current pipeline does, plus the two-stage family→subfamily assignment architecture discussed but not yet built. Teal = built and in use today. Rust = discussed, not implemented.

steps 1–8 — built hierarchical assignment — design only

Terminology

Definitions as used in this pipeline, fixed 2026-08-23 after a working session that corrected two earlier misreadings of "subfamily."

Family
A set of SINE copies sharing the same sequence "parts" — the same structural composition, still meaningfully alignable/collinear across their full mutual length.
Subfamily
A lineage within a family, defined by a specific, shared, diagnostic pattern of small indels/SNPs common to that lineage's copies — not generic per-copy decay.
Diagnostic pattern ≠ random decay. Ordinary post-insertion mutation is noise layered on top of the subfamily signal, not the signal itself.
Consensus
The reference sequence built for a family or subfamily (via SubFam / cons -plurality) and handed to asSINEment as a search target.
Leak
The mechanism that already exists for handling an ambiguous call — a locus that doesn't cleanly vote for one consensus over another. Used, not new, to absorb boundary-crossing between stages.
Firm / soft assigned
Firm = unanimous vote across all 10 ssearch36 cycles. Soft = majority but not unanimous. Both count toward total_assigned.
sim_mean
Mean per-copy bitscore over the consensus's own self-bitscore — how tightly a subfamily's assigned copies cluster around its consensus.

The workflow, with the fork as an actual split

Discovery through publish. At Step 2 the graph splits: the top branch is what's built and runs today; the bottom branch is the proposed hierarchical replacement, discussed but not implemented. Both branches rejoin before Step 3, since everything downstream of assignment is agnostic to how the assignment was produced.

Boundary crossing between the two proposed stages Handled by the existing leak mechanism, not a new one. Stage 2 never reconsiders a Stage-1 family call — a locus stays in its Stage-1 family regardless of how ambiguous Stage 2's subfamily vote is; ambiguity surfaces as a leak, same as today.

Step reference

Script names and outputs for each built step, for lookup alongside the graph above.

De novo discovery

sine_scan.sh / AnnoSINE_v2 + SubFam

Cross-species/structural search finds raw candidates from a genome with no prior library; manual clustering of SubFam chunk-consensuses produces the first family/subfamily hypothesis. Upstream of the pipeline proper.

out first-pass consensus candidates

Search & extract

step1_search_extract.sh

Cross-species / consensus homology search (sear) against the genome; candidate SINE loci extracted with flanks.

out genome.clean_step1/extracted.fasta
hover for detail

Assignment

step2_asSINEment.sh

10-cycle ssearch36 unanimous-voting assignment of every extracted locus to the best-matching consensus. Currently run flat: every known consensus, family or subfamily, competes as an equal peer — see the graph above.

out assigned.fasta, summary.by_subfam.tsv
hover for detail

Postprocess

step3_postprocess.sh

Collates per-subfamily assignment stats, self-bitscore normalization, leak/conf_alt tallies.

out assignment_stats.tsv

HTML report

Builds results/report.html. Must run after the results/ symlink farm rebuild, not before — fixed 2026-08-23 (was silently destroyed by a directory-rebuild race, reproduced across 4+ runs).

Boundary refinement

step7_boundary_refine.sh

Standalone. Tests flanks beyond each locus's current extraction boundary against background identity, extends where confirmed. Does not see structure hidden inside an already-extracted flank — a separate manual check found real signal inside the existing flank on t6-2/3/4 that this test missed.

out boundary_refinement.tsv

Alignments & publish

step8a_extract_alignments.sh / step8b_publish_report.sh

Re-extracts top100 / rand100 / subfam alignment variants per subfamily with real genomic flanks, wires links into report.html.
