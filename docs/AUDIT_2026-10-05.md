## 2. Audit: defects, ranked

Severity: how much a real run is misled, not how hard the fix is.

### D1 — the satellite stage cannot start in any orchestrated run since 2026-10-04 (high)

`satellite_stage.py` imports `satellite_kindB_verify` (line 36, added in `b9a6750`). `SINEderella` copies the stage into the
run directory and points `SINEDERELLA_TOOLS` at that copy, but the copy list (`SINEderella` lines 738–739, 893–894,
1060–1061) names `satellite_stage.py satellite_screen.py satellite_trf_verify.py array_order.py` only. Reproduced: copying exactly
those four files and running `satellite_stage.py --help` gives `ModuleNotFoundError: No module named 'satellite_kindB_verify'`.
Step 1 catches the failure (`|| echo WARNING`) and continues with the unfiltered hits, so the run completes and the report
shows no Satellites table. The toy tests did not catch it because they import from `tools/`.

Impact so far: none found. The last runs with the stage (`~/rhin/rsi_sat/run_20261003_202315`, `~/tmp/sdtest/run_20261003_202108`,
both 2026-10-03 20:2x) used the code before `b9a6750`, and no run directory newer than that exists under `~` (depth 5; genomes,
caches pruned). The Sicista Dip runs of 2026-10-03 04:47 predate the stage entirely (no `satellites.log`, no raw hits).

Fix: add `satellite_kindB_verify.py` to the three lists; make `mode_resume` copy `tools/` too (it refreshes every other script but
not the tools, and does not set `SINEDERELLA_TOOLS`); add a test that imports `satellite_stage` from a directory holding only the
files the orchestrator copies (parse the list from the `SINEderella` script so the two cannot drift again).

### D2 — the kind-B exclusion default is `flagged` in the pipeline, `verified` in the tool and the docs (medium)

`step1_search_extract.sh` line 135 passes `--exclude-b "${SATELLITE_EXCLUDE_B:-flagged}"`; `satellite_stage.py` defaults to
`verified`, and `docs/SATELLITES.md` 5h says `verified` is the default after the rsi/rle test. `PUBLISH_WORKFLOW.md` lists only
`flagged|all|none`. In a pipeline run the unit check is computed and written to `loci.bed`, but the exclusion follows the family
share: the rle MEG-RS case (26 verified arrays in a dispersed family, not SAT_B) stays in the SINE analysis, which 5h says it
should not. One line decides which rule the pipeline applies; the docs should name the same one.

### D3 — the report cannot show the criterion that excludes (medium)

`report_blocks._satellites` prints `kindB_runs`, `kindB_long_runs`, `kindB_excess_pct` and builds the Answer from `flag_B` and
the long-run count. `kindB_verified_arrays` (the column the `verified` rule acts on) is read into the table rows but never shown,
and a family with verified arrays and no SAT_B flag reads "–". Add the column and the sentence "N arrays verified by unit identity".

### D4 — `pytest tests` fails at collection (low)

`tests/toy/test_array_order.py` (a benchmark script taking `sys.argv[1]`, not a unittest) shares its basename with
`tests/test_array_order.py`; pytest stops with "import file mismatch". With `--ignore=tests/toy --ignore=tests/bench`: **57 passed,
1 skipped** (the consensus-audit end-to-end test needs mafft and gawk; run it on the server). Rename the toy script (e.g.
`toy_array_order.py`) or add `testpaths = tests` with `norecursedirs` to a `pytest.ini`.

### D5 — `sear` minimap2 mode (low; only queries ≥ 1 000 bp)

The comment and usage say "cascade asm5 → asm10 → asm20"; the loop (line 293) runs `asm10 asm20`. In this mode `taxname` is the
first three characters of the bank *path* (line 251: `"/ho"` for an absolute path); the ssearch36 branch overwrites it from the
part-file names, the minimap2 branch does not, so output names come out as `/ho-<query>.bed`. Harmless for SINE consensuses.

### D6 — candidate pairs cut by `--max-pairs` vanish from the length-version summary (low)

`length_variants_run.py` computes `untested` before truncating `pairs` to `--max-pairs` (lines 46–52); pairs beyond the cap are
neither tested nor listed as NOT_TESTED. They appear only in a stdout line.

### D7 — step 3 temp files go to `/tmp` (low on most hosts, worth fixing on therioserver)

`step3_postprocess.sh` line 47: `mktemp -d "${TMPDIR:-/tmp}/..."`, while step 2 and step 8a put their temp under the run
directory. `/tmp` is RAM on therioserver; for a Sicista-size run the per-subfamily `copies.fa` and `all_sim.m8` are hundreds of MB.
Same for `mode_add`'s `mktemp` (tiny file, no issue).

### D8 — thread caps not honoured in step 1 (low)

`step1_search_extract.sh` line 281 runs MAFFT with `--thread "$(nproc)"`; `SubFam` is called without a thread argument. `sear`,
the satellite stage and step 2 use `THREADS`. On a 64-thread-capped machine the SubFam alignment takes every core.

### D9 — `--add` bypasses the satellite screen; `--resume` has no tools (low)

`mode_add` searches the new consensuses with `sear` and rebuilds the BEDs (`rebuild_from_searches`) without running the stage, so a
family added later is never screened (the old families keep their exclusions, because the copied `gen-*.bed` are post-exclusion).
`mode_resume` (D1) copies no `tools/`.

### D10 — the stage reads the whole genome twice per consensus (performance)

`satellite_trf_verify.extract_windows` and `satellite_kindB_verify.verify_runs` each stream the complete genome FASTA for every
consensus. For 21 consensuses on rsi (2.1 Gb) that is 42 passes; a 60-consensus bank on a 3 Gb genome would spend most of the
stage reading. `samtools faidx` with a region file, or one pass collecting all windows of all consensuses, removes it.

### Documentation drift

* `docs/SATELLITES.md` line 3 still says "Nothing in this document is implemented yet"; sections 5d–5h describe the implementation.
* `MANUAL.md` §15 (environment variables) lists `THREADS CHUNK_BP FLANK` only; every variable added since 09-26 (`SKIP_SATELLITES`,
  `SATELLITE_EXCLUDE[_B]`, `SKIP_LENGTH_VARIANTS`, `LENGTH_VARIANTS_MAX_PAIRS`, `SKIP_CONSENSUS_AUDIT`, `CONSENSUS_AUDIT_JOBS`,
  `SKIP_CANONICALIZE`, `CANON_MIN_ID`, `SKIP_REBUILD_CONS`, `SKIP_ASSEMBLY_QC`, `SEARCH_GENOME`) lives only in `PUBLISH_WORKFLOW.md`.
  §4 (architecture) shows steps 1–4 only; §16.9 argues against any TRF pre-filter and now needs a pointer to the targeted one.
* `README.md`: the tool table lacks the satellite stage, `consensus_blocks.py`, `tsd_curve.py`; the dependency list lacks `trf`,
  `gawk`, numpy/matplotlib for the report; the step table skips step 6.
* `PUBLISH_WORKFLOW.md`: `SATELLITE_EXCLUDE_B` options incomplete (D2).

### What was checked and found sound

* `sear` raw-hit path: the fragment-to-genome conversion (`to_genomic`) uses the same offset arithmetic and `stripped.genome` as the
  filtered BED, and runs after that file exists; `@U@` restored in both files.
* `satellite_stage.py`: tuple layouts of the kind-A records (12 fields, identity at index 9, coverages at 10–11, the 10d9b1f fix),
  the 14-column `indication.tsv` header against its format string, the exclusion keyed per contig with a sorted overlap search,
  the attribution rule of 5h as described. Exclusion of a shared kind-A locus is applied through every consensus that matched it,
  before attribution, which is the intended behaviour (the locus is a satellite whichever consensus it is credited to).
* `step2_asSINEment.sh` (voting, thresholds, incremental tiers) and `step3_postprocess.sh` (LEAK, CONFLICT, soft assignment,
  summary) unchanged in the period and consistent with MANUAL §16.
* `canonicalize_consensus_bank.py` / `consensus_bank_lib.find_rc_clusters`: the new rules implemented as documented;
  `find_length_variant_pairs` uses an edit-distance prefix alignment (offset ≤ 10, +10..120 bp).
* `consensus_audit.py`: global alignment and verdict order (DIVERGED before UNSTABLE before length) as documented.
* `length_variants.py`: BTOP parsing, mode merging, linkage by frequency difference, TSD rule with shuffled control, as in the docs.
* `THREADS` propagation: a `THREADS=N SINEderella ...` call reaches `sear`, the stage and step 2 (environment inheritance); only
  the step 1 MAFFT/SubFam calls ignore it (D8).

### Harder (days; each is a method question, not a patch)

1. **Kind-A monomer as a SINE candidate** (SATELLITES.md §6, the user's first requirement): run each monomer consensus through
   SINEderella as a candidate, report which part of the SINE it carries and whether it is a short version in its own right; then the
   per-locus analysis of the 2023 paper (leading/trailing monomers, subvariants, homogeneity against locus length) and the CLsat-style
   expansion for array ends. The viewer exists; the characterisation step (`satellite_characterise`) does not.
2. **Kind-B unit characterisation**: the unit consensus per array (rsi 2 155 / 1 460 bp dimer), SINE positions in it, GC, internal
   repeats, and the link to the long-monomer satellite work (`longsat`, CLsat): one object described from both sides.
3. **flankscan open items**: chains deeper than 3 rounds and the open ends P9/P10/P21/P41; why the r3 internal repeat left the chain
   with builder v2; per-copy "carries the extension" in fs8 (one boundary per alignment follows a subgroup, HANDOFF 09-30).
4. **Calibration as a test, not a threshold**: the length-version and TSD rules use fixed thresholds set on rle/rsi; a permutation or
   bootstrap p-value per verdict would let a reader see how far from the line a call sits. The shuffled-pair controls already exist.
5. **Old copies the search cannot place** (MEG-T2 in rsi: 61–68 % identity, assigned by votes but no flank junction): nhmmer profiles
   from the top100 plates rescued 9 of 145 in the test (HANDOFF 09-30); a decision whether to add that tier.
6. **The modular / panconsensus model** (`RESEARCH_DIRECTIONS.md`, still "idea only"): flankscan's `units.tsv` already gives every
   window its units in consensus coordinates, so a per-copy presence/absence/order matrix over the candidate library is a reshaping of
   existing output; comparing it with the gradual model on the eri e2-3 bimodal case is the first experiment.
7. **Satellite screen on a de novo bank**: the stage assumes a consensus bank; on AnnoSINE/SubFam seeds (Sicista de novo) the raw
   hits of every seed would also show which seeds are satellite monomers before any assignment.
8. **A local-density null for kind B** (D24): the chance model for regular spacing spreads a family's hits uniformly over each
   contig. Families that follow isochores (Alu, B1) exceed it by 20 % on a single chromosome without one real array. Permuting hit
   positions within windows (1 Mb) keeps the regional density and would make the share flag mean what it says; until then the unit
   check decides, and the flag is information only.
